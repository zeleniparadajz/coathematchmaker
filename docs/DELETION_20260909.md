# Tournament And Match Deletion

## Administrator Workflow

- Global administrators get a delete icon in tournament and match details.
  Tournament owners/managers without the global admin role cannot delete.
- The confirmation page fetches a server preview, names the target, displays match/photo
  counts and requires acknowledgement that deletion is permanent.
- Tournament deletion removes all matches whose tournament foreign key points to it,
  regardless of status or whether they were added to the tournament.matches array.
  Results, result history and gallery references disappear with those records.
- Local gallery files are removed only when no remaining match, tournament or player
  references them. External images are not fetched or deleted. Shared locations,
  player accounts, profile photos and unrelated records remain intact.
- Applied wins/losses/matches/points are reversed for singles and doubles. Championship
  titles/points are reversed when they were awarded. Old points are never inferred from
  today's settings: the admin must supply missing historical match rates and, for legacy
  champions, state whether an award was made and enter its original value if applicable.
  A preflight check rejects deductions that would make existing counters or points negative.
- Friendly matches/tournaments never subtract ranking statistics.
- A match in a generated elimination draw, an established hybrid knockout round other
  than the terminal final, or a match feeding later rounds cannot be deleted individually.
  The page explains the restriction. Correct its result or delete the entire tournament.
  This is intentional: no dependent rounds or other matches are silently removed.
- A terminal final may be deleted. Its championship award is reversed and winner cleared.
  Hybrid final plans are removed so the previous round can generate a replacement;
  a two-player final resets knockout-start metadata. Empty draw metadata is cleared.
- Deleting an eligible match from a finished tournament clears its winner and returns it
  to active status; the confirmation explicitly discloses this.

## API And Reliability

Admin-only endpoints:

- GET /api/tournaments/:id/deletion-preview
- DELETE /api/tournaments/:id
- GET /api/matches/:id/deletion-preview
- DELETE /api/matches/:id

DELETE requires the preview revision and accepts legacyMatchPoints keyed by match ID,
legacyTournamentAwardApplied and legacyTournamentPoints. Changed records require a new
preview and confirmation (409). Invalid IDs, rates and roles are rejected before mutation.

A private DeletionJob records the authorized rollback plan before mutation. Each player's
counter decrement has a unique atomic marker. Retrying after a failed database/file operation
does not subtract counters twice. The job resumes before the next competition mutation and
at server startup. Completed jobs keep only a minimal idempotency receipt (IDs, actor, count,
timestamps), not scores, images or rollback deltas. There is no undo endpoint for deleted data.

The current deployment has one API process and standalone MongoDB. Match/tournament route
mutations are serialized by competitionHandler so deletion cannot race result confirmation,
draw generation or uploads in that process. **Do not scale API instances/workers without
adding a cross-process coordinator or MongoDB transactions.** Reads may briefly see partial
progress during deletion/recovery; this is not a multi-document transaction. Do not manually
remove pending jobs or statistics markers. Fix the underlying DB/filesystem error and retry.

New tournament awards record their original points and an operation marker; old champion
records remain untouched. The old non-hybrid bracket-completion path still records a winner
without awarding points, but now explicitly records that fact so deletion does not subtract
a nonexistent title. Recorded awards are idempotent and cannot silently move to another winner.

Deploy the backend before using these actions in the updated client. No database migration
or app build/version increment is required for the source change. No deployment was performed.

## Verification And Restore

- backend/test/deletion.integration.test.ts uses a unique isolated local Mongo database and
  uniquely named gallery fixtures. It checks cascade deletion, historic points, unrelated data,
  authorization, shared files, stale previews, interrupted rollback/award, retries and draw guards.
- test/deletion_test.dart covers confirmation, payload, success navigation, stale/error drafts,
  authorization controls and MNE/ENG layouts at 390px and 320px with enlarged text.
- .local-backups/deletion-20260909/before.tar.gz holds exact pre-deletion versions of touched
  existing files, including the previously uncommitted result corrections and match filters.
  Do not revert the entire worktree to remove this feature. Compare with this archive and
  preserve later work. New deletion-specific models, middleware, controller, service, screen,
  tests and this document are not in that archive.
- Code rollback does not restore data deleted through the feature. Recover deleted records
  only from a database/filesystem backup taken before deletion, keeping statistics consistent.
- No real tournament, match or production file was deleted during implementation or tests.
